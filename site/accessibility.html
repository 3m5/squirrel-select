Deutsche Fassung

In short

SquirrelSelect only changes how the native <select> looks. Keyboard, screen reader output and form validation stay with the browser.

Lists (multiple and size) keep the browser’s own keyboard and mouse behavior and screen reader output. Only borders, colors, spacing and the bold text of chosen options change.

  • Target: WCAG 2.2, level AA. This includes EN 301 549 and BITV 2.0, which refer to WCAG.
  • Method: self-assessment by the developers. No external audit.
  • Automated: axe-core, contrast calculation, keyboard and layout tests in Chromium 159, Firefox 159 and WebKit 27.2 (Playwright 1.65.1), on every change. All pass.
  • By hand, before every minor release: a short checklist on a real Android phone with TalkBack, and keyboard with zoom in Chrome, Edge and Firefox. Patch releases get a short smoke test. Not done yet for 1.0.0.
  • Not tested: VoiceOver on a real iPhone (WebKit with touch emulation is checked automatically), NVDA, JAWS, VoiceOver on macOS, the real Windows contrast themes, an external BITV test.

Status: 18 November 2026, before the 1.0.0 release.

Your part

The browser does most of the work, but these points are up to the page that uses SquirrelSelect.

  • Label every select. Each <select> needs a visible <label>. A placeholder option is not a label.
  • Golden rule: every option needs visible text. Icons and images are decoration: alt="" or aria-hidden="true". An aria-label does not replace the text, because the Firefox list, phones and the contrast mode show only the text.
  • Keep extra text short and separated. Put a space between the parts. The field reads them together, for example “Germany EUR”.
  • Give errors as text. Show the message next to the field and connect it with aria-describedby. The red border alone is not enough.
  • Keep contrast when you change colors. Text at least 4.5:1, borders and focus ring at least 3:1, in light and dark (light-dark()).
  • Keep the focus ring and the contrast mode. Do not remove the outline, and do not set forced-color-adjust: none on the select.
  • No buttons or links inside options.

Known limits

  • In Firefox on the desktop and in older browsers, the open list uses the system style. It is fully accessible, but does not match the rest of the design.
  • On phones and tablets, the system’s own picker opens on purpose.
  • In the Windows contrast mode, the browser’s own select appears on purpose, in the colors the user chose.
  • In Safari, selected options in a list keep the system highlight, and the row height comes from the browser. In Firefox and Safari, long option text in a list is cut off.
  • VoiceOver on macOS adds the word “group” to a select whose open list is styled. This comes from WebKit: one line of CSS without SquirrelSelect is enough. Name, value and state are read in full. Found in an automated trial, not yet confirmed in Safari on a real Mac.
