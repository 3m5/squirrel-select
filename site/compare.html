Compare

SquirrelSelect styles the browser's own <select>. Most select libraries take a different route: they hide the select and draw their own widget. Both approaches are valid. This page lays out the differences so you can pick the right tool for your form.

As of 18 November 2026. Every cell is based on the official documentation, repository or published npm package listed under Sources. Version numbers and sizes were checked on that date. If you spot something outdated, please open an issue.

In short

  • Choose SquirrelSelect if you want the native select to match your design without adding JavaScript, and you are fine with the open list coming from the operating system in Firefox and on phones.
  • Choose Tom Select, Choices.js or Slim Select if you need search, server-side loading, tags or free-text entries today, or if the open list has to look the same in every browser. They do more than SquirrelSelect, and they have done it for years.
  • Choose daisyUI if your project already uses Tailwind CSS. Its select follows the same idea as SquirrelSelect.
  • Do nothing if the default look is acceptable. The plain select is accessible, fast and works everywhere.

What SquirrelSelect does not do

  • It does not make the open list look the same everywhere. In Firefox and older browsers the operating system draws it; on phones people get the native picker on purpose. See browser support.
  • It does not add search, server-side loading or tags. An optional module for these is planned. Until then, the libraries above are the better choice for those forms.
  • It does not accept free-text entries, and this is not planned.

What it keeps: keyboard handling, screen reader support, autofill and form validation come from the browser, because the select stays a select. Our test results are on the accessibility page.
